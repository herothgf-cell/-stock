# 200티큐 자동 실행과 주문 복구

`200티큐 → 자동 실행 · 주문 상태`는 앱을 열어 둔 동안 신호를 점검하고,
매도와 후속 매수를 순서대로 처리하는 실행 화면이다. 기본값은 `DRY_RUN`이다.
실제 주문은 `LIVE`를 선택하고 계좌·USD 상한·현금거래 계좌 여부를 확인한 뒤
이 PC에서 직접 허용해야 한다. 허용 상태는 앱을 종료하면 사라진다.

실주문 자동 실행 시간은 **같은 거래일의 정규장 종료 10분 뒤부터 시간외 종료 전**이다.
전날 종가를 다음 정규장 중에 뒤늦게 자동 실행하지 않는다. 통상 뉴욕 16:10 이후이며,
조기 종료일과 서머타임은 거래소 달력·시간대로 계산한다. NH가 해당 시간외 거래 상태를
확인해 주어야 주문할 수 있다. 읽기 전용 주문 대조는 이 시간 제한과 별개로 제공한다.

사용자가 제공한 2026-05-07 행동 매뉴얼의 전략 판단은 `strategy.py`가 담당한다.
제공받은 참고 프로젝트에서는 주문 의도 선저장, 전량 체결 후 다음 단계 진행,
재시작 대조라는 구조를 검토했다. 그 프로젝트의 전략 기본값·종목·과열 규칙을
이 프로그램에 가져오지 않았다. 구현은 별도 모듈과 SQLite 저장소로 작성했다.

## 시작하기

1. 실제 원장을 가져오고, 실행할 NH 일반 계좌 하나를 연결한다. 전체 계좌 화면에서는 실행할 수 없다.
2. 전략 화면에서 분할 매수용으로 배정한 현금/SGOV 예산, 기존 사이클, 익절 단계,
   최신 완료 종가와 분할 보정 여부를 확인한다. 배정하지 않은 예수금을 자동으로 새 자금으로 분류하지 않는다.
3. `DRY_RUN`과 주문 상한을 설정한 뒤 자동 실행을 시작한다. 주문 순서·예상 수량·지정가·차단 사유를 확인한다.
4. 실주문이 필요하면 모의 실행을 중지하고 `LIVE`를 선택한다. 현금거래 계좌 확인을 체크하고
   계좌 별칭, 1회 주문 상한, 실행당 총 매수 상한을 확인해 직접 허용한다.
5. 앱을 켜 둔다. 완료 후에는 실제 NH 체결 내역을 가져와 원장과 전략 단계를 확인한다.
   실제 체결 반영이 끝나기 전에는 다음 자동 실행이 시작되지 않는다.

다른 PC에서는 기록을 볼 수 있지만 **실주문 자동 실행은 한 PC에서만 사용한다.**
자동 실행 상태·주문 의도·재개 상태는 거래 원장 동기화에 포함하지 않는다.
실행 데이터베이스를 다른 PC에 복사하면 소유 PC 식별자가 달라져 열거나 재개할 수 없다.
별도 PC의 새 설치까지 묶는 중앙 주문 잠금은 제공하지 않으므로, 여러 PC에서 동시에 허용하면 안 된다.
분산 환경의 주문 1회 실행을 보장한다고 주장하지 않는다.

## 실제 주문이 허용되는 조건

실행기는 계획을 한 계좌·한 종가 자료 해시·한 자료 출처에 고정한다. 다음 조건이
충족되지 않으면 주문을 보내지 않고 사유를 표시한다.

- 선택한 원장 계좌, 연결한 NH 계좌 지문, 신호 자료의 계좌가 일치한다.
- 완료 정규장 종가가 최신 거래일과 일치하고, 분할 보정과 최신성 확인이 그 자료 해시에 해당한다.
- 전략에 해결되지 않은 확인 사항이 없으며, 자동 주문 수량이 정수 주수다.
- 익절 신호라면 같은 종가 날짜의 환차손을 포함한 증권사 수익률이 확인되어 있다.
- 미국 거래 달력과 NH가 표시한 현재 거래 구간이 일치하고, 허용된 세션 안이다.
- 증권사의 보유 수량, 실제 주문 가능 USD, 미체결 주문을 완전하게 조회했다.
- TQQQ·SPYM·SGOV의 실제 보유 수량이 원장과 이 실행에서 확인한 체결의 합계와 일치한다.
- 다른 미체결 주문, 미정리 실행, 원장 반영 대기 실행이 없다.
- 주문 직전 시세와 잔고가 유효 시간 안에 있고, 예산과 주문 상한을 넘지 않는다.

거래 달력의 지원 범위, 조기 종료, 현재 세션 확인과 실제 계좌 권한은 서로 다른 확인이다.
달력만 맞다고 NH 주문 가능 상태를 가정하지 않는다. 자료 보정 여부를 확인하지 못하거나
NH 응답의 의미를 확정할 수 없으면 자동 실행이 차단되는 것이 정상이다.

## 주문 순서와 금액

| 전략 단계 | 실행 순서 | 다음 단계의 조건 |
|---|---|---|
| TQQQ 분할 진입 | 필요할 경우 배정한 SGOV 일부 매도 → TQQQ 매수 | SGOV 전량 체결, 실제 USD 가용 현금, 원래 분할 예산 확보 |
| TQQQ 익절 | 해당 정수 주수 매도 → SPYM 매수 | TQQQ 전량 체결, 실제 매도대금 가용 현금 증가 |
| 200일선 이탈 | TQQQ 전량 매도 → SPYM 전량 매도 → SGOV 매수 | 두 종목 매도 전량 체결, 매도대금 가용 현금 증가와 명시적으로 배정한 잔여 전략 현금 |
| 기존 SPYM 대기금 | 확인된 익절 대기금 범위에서 SPYM 매수 | 실제 가용 USD, 남은 대기금과 매수 상한 확인 |

SGOV를 매수 자금으로 쓸 때는 신호에 그 자금 배정이 명시되어 있어야 한다.
SPYM을 TQQQ 진입 자금으로 매도하지 않는다. SGOV 전량을 무조건 처분하지 않고
해당 분할 매수에 부족한 현금과 비용 여유를 충당할 정수 수량을 계산한다.
SGOV를 먼저 팔았더라도 그 대금을 실제로 쓸 수 있다는 NH 응답을 받기 전에는 TQQQ를 사지 않는다.

매수 지정가는 신선한 현재가의 `1.001`, 매도 지정가는 `0.999`를 기준으로 소수 둘째 자리로
계산한다. 이 가격이 체결을 보장하지 않는다. 주문 수량은 매수 예산, 지정가, 기본 0.5%의
수수료 여유를 사용해 정수로 내린다. 수수료 여유율과 가격 배율은 실행 정책에 저장되며
화면에서는 기본값을 사용한다.

**분할 매수의 원래 예산이 주문 상한보다 크면 실행을 차단한다.** 상한에 맞춰 아주 일부만
사고 1/2/3차를 완료로 표시하지 않는다. 전량 매도 계획도 주문 상한을 넘으면 조용히 일부로
줄이지 않고 차단한다. 1주를 살 수 없는 잔돈은 단계를 성공으로 처리하지 않는다.

익절 대금의 후속 SPYM 매수는 확인된 순매도대금, 실제 가용 현금 증가, 남은 총 매수 상한
안에서만 진행한다. 수수료·세금을 모두 확인하면 실제 차감액을 사용하고, 미확인 비용이
있으면 기본 여유율을 남긴다. 상한·정수 수량 때문에 남은 금액은 전략의 대기금으로 남는다.
NH 체결 응답이 비용을 제공하지 않는 경우에는 별도의 비용 검토가 필요하며, 0원으로 확정된
비용과 미확인 비용을 같은 의미로 취급하지 않는다.

하락 전환의 자동 SGOV 매수는 **이 실행에서 확인한 매도대금과 명시적으로 배정한 잔여 전략 현금**을 대상으로 한다.
잔여 전략 현금은 실제 매도 전 가용 USD를 넘을 수 없으며, 이미 SGOV로 보유한 금액은 다시 현금으로 세지 않는다.
원장과 분리된 임의의 예수금·새 입금·다른 전략 자금을 자동으로 함께 투입하지 않는다.
체결 후에는 매도대금의 실제 가용 현금 증가와 처음 확인한 배정 현금 안에서만 매수한다.

## 상태의 의미

| 표시 | 의미와 다음 행동 |
|---|---|
| `RUNNING` | 검증 가능한 다음 단계 또는 주문 상태 조회를 진행한다. |
| `WAIT_CASH` | 매도는 확인했지만 필요한 실제 USD 가용 현금이 아직 부족하다. 새 매수는 보내지 않는다. |
| `SIMULATED` | 가정한 지정가 체결 결과다. NH 주문도, 실제 체결 원장 변경도 없다. |
| `COMPLETE` / 체결 원장 반영 대기 | 모든 주문의 전량 체결을 확인했다. 실제 NH 체결을 가져오고 전략 단계에 반영해야 한다. |
| `COMPLETE` / 반영됨 | 실제 체결과 전략 진행 기록의 저장을 확인했다. 다음 신호 평가를 진행할 수 있다. |
| `BLOCKED` | 자료 불일치, 일부 체결, 응답 불명, 거절, 취소, 마감 등으로 새 주문을 차단했다. |
| `REVIEW_REQUIRED` | 재시작 또는 조회 대조 이후 직접 확인이 필요하다. 자동으로 다음 주문을 보내지 않는다. |
| `NO_ACTION` | 현재 신호에 실행할 주문이 없다. |

개별 주문의 `INTENT`는 **서버 호출 전에 디스크에 저장한 주문 의도**다. `SUBMITTED`는
주문 접수 또는 대기 상태이며 체결 확정이 아니다. `FILLED`는 요청 수량 전체, 체결 가격,
주문 식별자와 관측 시각의 일관성을 확인한 상태다. 지정가 조건과 맞지 않는 체결 응답도
확정으로 처리하지 않는다. `CANCEL_REQUESTED` 역시 취소 완료를 뜻하지 않는다.

## 응답 불명과 재시작

NH 해외 주문의 확인된 API 계약에는 서버가 중복을 막아 주는 `clientOrderId` 필드가 없다.
프로그램의 `intent_id`는 로컬 중복 방지 식별자이며 NH 서버의 주문 멱등성 키가 아니다.
따라서 요청 후 시간 초과, 통신 중단, 잘못된 응답이 나면 그 주문은 `UNKNOWN`으로 남긴다.
같은 주문 POST를 자동 재전송하지 않는다. 인증 갱신이나 429 응답 처리에서도 주문 전송을
재시도하지 않는다.

실행 데이터베이스는 주문 의도, 요청 수량/지정가, NH 주문 식별자, 관측한 체결, 후속 순서,
예산과 확인 자료를 저장한다. 같은 전략 단계의 실주문을 새로운 실행으로 다시 만들 수 없다.
데이터베이스 저장에는 SQLite 트랜잭션과 `synchronous=FULL`을 사용한다.

프로그램이 주문 의도를 저장한 뒤 접수 응답을 저장하기 전에 중단되면, 실제 전송이
이루어졌는지 알 수 없다. 다음 실행에서 `UNKNOWN`으로 바꾸고 자동 재개를 차단한다.
주문 번호조차 받지 못한 건은 시간·종목이 비슷하다는 이유만으로 임의 주문과 연결하지 않는다.
사용자는 NH 앱의 주문 내역과 잔고를 확인해야 한다.

주문 식별자가 있는 건은 `NH 상태 대조 (조회만)`으로 읽기 전용 확인을 할 수 있다.
접수 때의 비밀정보 없는 주문 문맥과 NH 주문 번호를 보존하여 재시작 후에도 계좌, 종목,
매매 방향, 수량, 지정가, 날짜 후보를 대조한다. 모호한 응답이나 서로 다른 날짜의 복수 후보는
불명 상태로 남긴다. 조회 대조만으로 재주문하거나 다음 단계로 넘어가지 않는다.

일부 체결 후에는 후속 매수도 차단한다. 이후 NH에서 전량 체결이 확정되었다면 상태 대조 후,
고정된 신호가 여전히 유효하고 최신 확인 자료·현금·보유·세션 조건이 맞을 때 직접 재개할 수 있다.
거절·취소·부분 체결·식별 불명인 주문을 자동으로 새 주문으로 바꾸는 기능은 없다.

## 마감, 중지와 앱 종료

새 주문의 마감은 정책에 저장한 마감과 확인된 거래 세션 종료 중 더 이른 시각이다.
기본적으로 세션 종료 30초 전부터 새 주문을 막는다. 앱이 계속 실행되고 해당 계좌의 실주문이
허용된 상태라면, 마감에 남아 있는 식별 가능한 미체결 주문을 한 번 취소 요청하고 결과를 확인한다.
취소 응답이 불명확하면 취소 POST도 반복하지 않는다. 일부 체결·취소 요청만으로 후속 매수를 허용하지 않는다.

`새 주문 중지`는 다음 주문 제출을 중지한다. NH에 이미 접수된 주문을 일괄 취소하는 버튼이 아니다.
닫기 역시 먼저 타이머와 신규 주문을 막고, 결과 미확정 주문이 있으면 이미 접수된 주문이
계속 체결될 수 있다는 확인을 표시한다. 닫기를 취소해도 자동 허용은 해제된 상태로 남는다.
주문 직전 API 검증 중에 중지를 눌러도 최종 HTTP 쓰기 직전에 중지 신호를 다시 검사한다.

앱이 꺼진 동안 작업 스케줄러·서비스·백그라운드 프로세스가 자동 주문을 수행하지 않는다.
전원이 꺼지거나 네트워크가 끊기면 마감 취소 요청도 수행할 수 없다. 이미 접수된 주문은
증권사의 정책에 따라 처리되므로 NH 앱에서 확인해야 한다.

## 개발 및 검증 범위

- `stockjournal/automation.py`: 정확한 소수 계산, 한 계좌 실행 정책, 독립 실행 DB,
  주문 의도 선저장, 단계별 실행, 전량 체결 검증, 현금 대기, 조회 대조와 재개 차단.
- `stockjournal/automation_ui.py`: Tk 타이머, 한 번에 하나의 작업 스레드, 지역 허용,
  상태표·이벤트 기록, 중지와 종료 확인. 네트워크 스레드에서 Tk 객체를 조작하지 않는다.
- `stockjournal/nh_execution.py`: 공식 NH 해외 주식 지정가 주문·취소·조회 계약을 구현한 어댑터.
- `stockjournal/automation_integration.py`: 선택 계좌와 최신 자료 준비,
  실제 NH 체결 중복 제거·원장 반영·전략 단계 확인.

시험은 합성 브로커와 고정 응답으로 수행한다. 중복 호출, 제출 전 저장, 제출 응답 손실,
재시작, 부분 체결, 실제 현금 대기, 두 종목 매도 후 SGOV 전환, 마감 취소,
취소 응답 손실, 계좌 불일치, 오래된 시세, 미체결 주문, 주문 상한, 다른 PC 소유,
실제 원장 반영 대기, 중지 중 늦은 HTTP 전송, UI 초기화 중 중지 경합을 검사한다.
이 시험은 실제 NH 계좌의 접근 권한·시세 권한·주문 가능 여부나 실거래 체결 성공의 증명이 아니다.
개발 과정에서 실제 계좌 주문을 실행하지 않는다.

확인한 주문 계약의 출처: [NH PLUG 공식 해외 주식 OpenAPI 명세](https://www.nhplug.com/openapi-docs/gbstock/openapi.json).
행동 기준: [사용자 제공 2026-05-07 200티큐 매뉴얼](https://www.fmkorea.com/9797763685).
참고 구조의 배포 파일이나 개인 계좌 원본은 공개 코드·실행 파일에 포함하지 않는다.
