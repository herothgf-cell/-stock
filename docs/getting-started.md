# 사용 가이드

## 계좌와 매매

배포 ZIP을 풀고 `StockJournal.exe`를 실행합니다. **설정 · 계좌**에서 실제 계좌번호 대신 알아보기 쉬운 별칭을 등록하세요. 계좌 종류는 일반·ISA·연금저축·IRP·DC·기타를 선택합니다. **종목 관리**에서 공식 국내 종목 목록을 받거나 해외 상장 종목을 직접 추가합니다.

국내에 상장된 해외지수 ETF는 한국/KRW입니다. 상장 시장과 기초자산의 지역을 혼동하지 마세요. 종목 이름·코드로 검색할 수 있습니다.

**매매 기록**에서 매수·매도·기초 보유를 입력합니다. 수수료와 세금은 실제 금액입니다. 날짜는 `YYYY-MM-DD`, 시간이 있으면 `YYYY-MM-DDTHH:MM:SS`로 입력합니다. 같은 시각의 거래는 처리 순서 숫자로 정렬합니다. 보유 수량을 넘는 매도는 저장하지 않습니다. 기초 보유는 실제 수량과 취득 단가를 확인해야 합니다.

대시보드에서 매도 완료 종목까지 이력을 확인합니다. 종목을 더블클릭하면 해당 계좌·종목 거래를 볼 수 있습니다. 서로 다른 통화는 환율 없이 합산하지 않습니다. 가격 미조회 시 평가는 비워 둡니다. 해외 종목 등은 **종목 관리 → 가격 직접 입력**으로 평가 가격을 저장할 수 있습니다.

## 엑셀·CSV·채팅·이미지

**일괄 가져오기**는 원장에 바로 저장하지 않습니다. 파일 선택 또는 텍스트 분석 후 후보 행의 날짜·계좌·종목·수량·가격·비용을 검토하세요. 빨간 행은 필수 정보가 빠졌거나 값 확인이 필요한 행입니다. 더블클릭 또는 **선택 행 수정**으로 확인한 뒤 저장합니다.

기존 `매매일지` 시트의 물량별 엑셀 형식을 지원합니다. 완료 행의 K열 값을 매도가로 보는 것은 원본 구조에 따른 추정입니다. 실제 체결가와 비교하세요. 매도가가 수식이거나 매도일이 매수일보다 빠르면 연결된 매수·매도 둘 다 차단합니다. 완료 물량은 양쪽을 함께 수정·선택해야 합니다. 수수료·세금이 없는 원본은 0과 확인 경고를 제안합니다.

일반 거래 CSV 예시입니다. 모든 예시는 합성 자료입니다.

```csv
account,code,name,market,currency,executed_at,side,quantity,price,fee,tax,external_id
테스트계좌,005930,삼성전자,KR,KRW,2026-10-01,BUY,10,70000,100,0,order-1
```

채팅 예시: `2026-10-01 매수 005930 10주 70000원`. 날짜가 없다면 화면의 기본 날짜를 적용하고, 계좌는 저장할 계좌에서 지정합니다. 종목명만 있거나 모호한 문장은 직접 수정해야 합니다. 원본의 외부 식별자로 중복을 확인하지만 서로 다른 파일 형식 간 동일 거래를 자동 판별하지는 않습니다. 같은 자료를 여러 경로로 가져오면 중복을 직접 확인하세요. 원본 행을 재배열하거나 변경하면 식별자 없는 행이 새 거래로 인식될 수 있습니다.

OCR은 Windows 내장 `Windows.Media.Ocr`를 이용합니다. 이미지를 외부 OCR 서비스로 보내지 않습니다. Windows의 한국어 OCR 언어 기능이 필요할 수 있습니다. 인식된 텍스트와 숫자는 직접 검토한 뒤 저장하세요. 언어팩이나 이미지 형식 오류가 나면 텍스트·CSV를 사용할 수 있습니다.

## 배당

**배당 관리 → 수령 추가**는 실제 입금된 세전 금액과 세금을 기록합니다. 순수령액이 손익에 반영됩니다. 참고·공시 일정의 주당 배당금은 실제 입금액에 합산하지 않습니다. 현재 보유 종목에 연결된 일정을 표시합니다. ETFcheck 버튼은 사이트 검색용이며 자동 수집하지 않습니다.

배당 CSV는 거래 CSV와 별도 파일로 작성합니다.

```csv
code,name,record_date,pay_date,amount_per_share,currency,status,source
0001A0,테스트 ETF,2026-10-20,2026-10-30,12.5,KRW,announced,공식 공시
```

```csv
account,code,market,paid_date,gross,tax,currency,source
해외계좌,AAPL,US,2026-10-24,100.25,15.03,USD,증권사 원장
```

참고 일정의 `status`는 `reference` 또는 `announced`입니다. 일괄 가져오기 화면에서 배당 행을 수정하거나 제외할 수 있습니다.

## NH 데이터 연결

나무 PLUG의 운영 앱키·시크릿을 앱 설정에 직접 입력합니다. 서비스 가입·조회 권한·지원 계좌는 NH 정책에 따릅니다. 현재가는 앱 실행 중 30초 이상 간격으로 조회합니다. 초 단위 체결 스트리밍은 아닙니다. 앱과 PC가 종료되면 자동 조회도 중단됩니다.

**NH 체결 조회**에서 계좌와 기간을 지정합니다. 결과는 주문별 누적 체결이므로 같은 주문을 다시 조회한 경우 검토 후 갱신 허용을 선택하세요. 수수료·세금은 원장과 대조해야 합니다. 조회 기간 이전 매수분은 먼저 과거 거래나 기초 보유로 등록하세요. 신용·정정 연결 주문 등 지원하지 않는 내역은 수동 검토가 필요합니다.

## 다른 PC와 기록 공유

1. GitHub에서 코드 저장소와 별도로 **Private** 저장소를 만듭니다. 예: `my-stock-journal-data`. README를 포함하면 기본 브랜치 확인이 쉽습니다.
2. GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens에서 해당 저장소에만 접근하는 토큰을 발급합니다. **Contents: Read and write** 권한이 필요합니다.
3. 앱 설정에 `소유자/저장소`, 브랜치(보통 `main`), 토큰을 넣고 저장한 뒤 동기화합니다. 빈 저장소의 첫 연결에는 기본 브랜치를 사용합니다.
4. 다른 PC에서도 같은 저장소를 설정합니다. 토큰·NH 키는 PC마다 입력합니다.
5. PC를 바꾸기 전 동기화를 완료하고, 새 PC에서도 동기화 후 작업합니다.

독립적으로 추가한 기록은 병합합니다. 같은 기록을 양쪽에서 수정하면 두 값을 보고 사용할 내용을 선택합니다. 충돌 검토 중 원격이 다시 변경되면 다시 확인해야 합니다. 원격 기록을 강제 덮어쓰지 않습니다. 오프라인에서는 로컬 저장이 가능하며 다음 동기화 때 반영됩니다.

## 백업과 복원

기본 데이터 폴더는 `%LOCALAPPDATA%\StockJournal`입니다. SQLite 원장, 자동 백업, 설정·가격 캐시·암호화 인증값을 별도로 보관합니다. 중요한 변경 전 **기록 백업 내보내기**로 JSON을 보관하세요. CSV는 조회용이며 ID를 보존하는 전체 복원에는 JSON을 사용합니다.

과거 백업 복원과 원격 동기화는 별개입니다. 복원 후 원격 기록과 다시 병합할 때 원격 변경이 돌아올 수 있습니다. 파일에서 항목을 수동으로 지우는 대신 앱의 삭제 메뉴를 사용하세요. 삭제 표시를 통해 다른 PC에 전달합니다.

앱 실행 실패 시 데이터 폴더의 `startup-error.log`를 확인합니다. 원장 파일을 지우고 시작하지 마세요. 같은 데이터 폴더를 사용하는 두 번째 앱은 잠금으로 실행을 거부합니다.
