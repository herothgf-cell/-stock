# 나무 연동과 200티큐 지원

## 요청과 기존 구조

Windows tkinter 매매일지에 나무 계좌·잔고·체결 조회, 미국 종목 시세,
200티큐 판단 보조를 추가한다. 다른 증권사 계좌는 수동 관리한다.
기존 Google Sheets를 실제 초기 데이터의 출처로 사용한다.
사용자는 저장소를 clone해서 실행하므로 검증된 EXE를 저장소 루트에 게시한다.

## 구현 선택

기존 Python/SQLite/비공개 원장 동기화를 유지한다. 별도 웹 서비스나
매매 주문 서버를 추가하지 않는다. 공식 나무 REST 조회 기능을 확장한다.
계좌 발견 결과는 기존 계좌에 연결하거나 새 별칭으로 등록한다.
계좌번호는 PC별 DPAPI 비밀 저장소에만 저장한다.
조회 잔고는 원장과 비교하는 스냅샷이다. 과거 거래가 없는 종목만 사용자가
검토한 뒤 기초 보유로 넣을 수 있으며, 기존 매수에 잔고를 더하지 않는다.

## 200티큐 기준

사용자가 제공한 아기티큐 2026-05-07 행동 매뉴얼
(https://www.fmkorea.com/9797763685)을 기준으로 한다.
TQQQ 정규장 종가의 200일선 상향 돌파 후 현금 1/3, 남은 현금 1/2,
나머지 현금으로 3일 분할 진입한다. 이탈하면 TQQQ와 SPYM을 SGOV로
전환한다. 최초 수익률 10/25/50%에서 잔량 10%, 100/200/300% 이후
100%p마다 잔량 50%를 익절하고 SPYM으로 전환한다.
수익률은 환차손익을 고려하므로 증권사 표시 수익률을 입력할 수 있어야 한다.
추가 자금은 상승 구간 SPYM/SGOV 절반씩, 하락 구간 SGOV로 표시한다.
판단 화면은 실제 주문을 제출하지 않으며 원장 체결을 확인한 뒤 단계 완료를 기록한다.

원문 미정 사항은 구현 선택으로 공개한다: 200거래일 단순평균, 동률 대기,
정수 주수 반올림, 갭 상승으로 여러 익절 단계를 통과하면 검토 대상으로 표시.
미국 거래일과 서머타임을 인식하며 미완성 봉은 사용하지 않는다.
NH 일봉의 분할 보정은 문서에서 확인되지 않으므로 unknown을 유지하고,
데이터 확인 전 신호를 확정하지 않는다. 보정 종가 CSV를 사용할 수 있게 한다.

## 개인 초기 기록

공개 코드 저장소와 EXE에는 개인정보·계좌 원본·인증키를 포함하지 않는다.
실제 Google Sheet를 내보내 파싱하고 유효한 기록을 개인용 초기 원장으로
구성한다. 값이 모호한 완료 거래는 매수/매도 양쪽을 함께 보류한다.
초기 원장에는 제외된 행과 확인 이유를 함께 보관하여 조용히 유실하지 않는다.
앱에서 초기 입력 파일을 선택하면 검토 가능한 초기 내역과 보류 항목을 가져온다.
원본 Google Sheet는 수정하지 않는다.

## 배포

Windows CI에서 단위 검사, 7개 화면, 실제 EXE 실행을 통과한 동일 소스만
StockJournal.exe와 SHA-256/소스 커밋 정보를 main에 게시한다.
새 소스가 먼저 게시되면 오래된 빌드는 배포하지 않으며 강제 push하지 않는다.
인증 API의 실제 사용자 접속은 키가 없는 상태에서 완료로 주장하지 않는다.

## 검증

중복 체결, 기존 보유와 잔고 중복, 초기 파일의 보류 자료, 손익 통화,
일봉 부족·미완성·분할 불명, 반복 익절, 계좌/시뮬레이션 혼동을 검사한다.
소스와 EXE의 Windows 실행 결과를 기록하고 실제 EXE의 Git blob도 확인한다.

## 추가 요청: 첨부 자동매매 프로그램의 실행 구조

이후 사용자가 toss-trader-release3.96(1).zip 소스를 제공하고 자동매매 구조를
참고해 재검토·개발하라고 요청했다. 참고 소스는 실행하지 않고 읽었다.
전략 규칙과 실행 구조를 나눠, 참고 프로그램의 과열·추가 손절·익절 기본값은
5월 7일 전략에 섞지 않는다. 주문 전 로컬 영속 계획, 계좌/기기 식별,
부분 체결/불명 응답 중단, 완료 체결 후 다음 주문, 재시작 대조를 적용한다.

자동 실행은 DRY_RUN을 기본으로 하며 실제 체결을 만들어 원장에 쓰지 않는다.
LIVE는 사용자가 앱에서 미국 현금 계좌·예산을 확인하고 현재 실행에서 명시적으로
켜야 한다. 실제 주문/취소 코드는 공식 NH 미국 정수주 지정가 명세를 따르며,
개발 과정에서는 실제 주문을 호출하지 않는다. NH에는 클라이언트 멱등 주문키가
없으므로 전송 결과 불명 상태에서 재전송하지 않는다.

실행 상태는 로컬 전용이며 개인 원장 동기화로 다른 PC의 자동매매를 재개하지 않는다.
달력은 공식 예정 휴장/조기 종료와 NH 관측 시장 상태를 함께 검사한다.
가격 보정·실제 잔고·가용 현금·최근 거래일을 검증하지 못하면 실행을 차단한다.
