# 데이터 출처와 NH 연결 범위

이 앱의 NH 조회 연결은 **국내 종목 목록, 연결 계좌, 국내·미국 잔고·현재가·누적 체결 내역, TQQQ 일봉**에 사용합니다. 가격은 조회 시점의 폴링 결과입니다. **실제 주문은 별도의 자동 실행 경로에서 LIVE를 명시적으로 활성화했을 때 제출합니다.** 계좌 목록·잔고·체결·시세 조회 버튼은 주문을 제출하지 않습니다. 처음 연결할 때는 [실제 API 연결 안내](nh-api-connection.md)를 따르세요.

## 검증 상태

2026-10-31 개발 환경에서 NH의 공개 종목 마스터를 실제로 내려받아 파싱했습니다. 당시 파일은 **1,021,233바이트, 4,309종목**이었으며, 분류 결과는 주식 2,769개, ETF 1,183개, ETN 357개였습니다. 종목 수와 파일 내용은 거래소 및 NH의 갱신에 따라 달라집니다.

앱 키가 필요한 인증·현재가·계좌 체결 조회는 공식 문서와 HTTP 응답 픽스처로 검증했습니다. **실제 사용자의 NH 앱 키와 계좌로 연결한 결과는 아직 검증하지 않았습니다.** 사용자는 NH PLUG에서 발급한 키와 해당 계좌의 조회 권한으로 연결을 확인해야 합니다.

Windows DPAPI의 실제 암호화·복호화·변조 검출 테스트는 Windows에서 실행하도록 구성되어 있습니다. Linux에서는 이 테스트를 건너뛰며, 플랫폼을 모의한 테스트로 암호화 경계, 파일 교체 실패, 복원 및 평문 저장 금지를 검증합니다.

## 1. 국내 종목 마스터

출처: [NH 공개 국내 종목 마스터](https://www.nhplug.com/instruments/m_new_stock.mst).

이 다운로드에는 앱 키나 계좌번호가 필요하지 않습니다. 파일의 각 레코드는 CP949로 인코딩한 데이터 236바이트와 LF 1바이트로 구성됩니다. 이름의 한글 글자 수가 아니라 **원본 바이트 위치**를 기준으로 읽습니다. CRLF와 마지막 줄바꿈 생략도 처리합니다.

| 항목 | 원본 위치: 시작 포함, 끝 제외 | 앱에서의 처리 |
| --- | --- | --- |
| 종목코드 | `0:6` | 영문·숫자 6자리. `0000D0` 같은 코드와 앞자리 0을 보존 |
| 시장 구분 | `6:7` | 자산 분류에 사용하며 앱의 시장은 `KR`로 저장 |
| 종목명 | `7:48` | CP949로 해석하고 이름 앞의 `*` 표시 제거 |
| ETF 구분 | `165:166` | 시장 구분 `1`이면서 값이 `8`이면 ETF |
| ETN 구분 | 시장 구분 | 시장 구분 `A`이면 ETN |
| 업종 코드 | `199:205` | NH 원본 코드 보존. 업종명으로 추정 변환하지 않음 |

저장 식별자는 `KR:<종목코드>`, 통화는 `KRW`이며, 분류는 `주식`, `ETF`, `ETN`입니다. 손상된 문자, 잘못된 길이, 빈 이름, 중복 코드, 빈 레코드가 있으면 전체 다운로드를 거부합니다. 정상 레코드만 일부 저장하는 방식은 사용하지 않습니다.

## 2. 인증과 현재가

접속 대상은 `https://api.nhplug.com:8443`로 고정되어 있습니다. 나무 NH PLUG 운영 서버용이며 N2·모의투자 서버로 전환하는 설정은 제공하지 않습니다. HTTPS 인증서를 검증하고 모든 HTTP 리디렉션을 차단합니다.

공식 SDK의 인증 규약에 따라 `POST /oauth2/token`의 쿼리에 `appkey`, `appsecretkey`, `grant_type=client_credentials`, `scope=oob`를 넣습니다. 본문은 비워 두고 콘텐츠 유형은 `application/x-www-form-urlencoded`로 보냅니다. 쿼리에 비밀 값이 포함되므로 오류 화면과 예외 메시지에 요청 URL이나 서버 원문을 표시하지 않습니다.

인증 후 조회는 Bearer 토큰만 사용합니다. 2026-10-15 공식 안내 `llms.txt`는 `x-client-id`, `x-client-secret`이 불필요하다고 명시합니다. 과거 SDK의 중복 헤더를 추가하지 않습니다. 앱 키와 토큰에 줄바꿈·제어문자를 허용하지 않습니다.

| 조회 | 엔드포인트 | 주요 입력 | 사용 값 |
| --- | --- | --- | --- |
| 현재가 | `/krstock/quote/v1/currentPrice` | `Input_0.iem_cd`, `market_cd=UNT` | `Output_0.stck_prpr` |
| 일별 체결 | `/krstock/inquiry/v1/dailyOrderExecution` | `orr_dt=YYYYMMDD`, `act_no`, `orr_mkt_cd=00`, `ost_cns_dit=1` | `Output_0`의 주문별 누적 체결 |
| 연결 계좌 | `/n2/acctinfo` | 빈 `Input_0` | `acct_no`, `acct_type`; 01·02 운영, 03 모의 |
| 국내 잔고 | `/krstock/inquiry/v1/balance` | 연결 계좌, 조회 구분 | 종목별 수량·원가·평가; 원장과 대조 |
| 미국 잔고 | `/gbstock/inquiry/v1/balance` | 연결 계좌, 미국 200, USD | 종목별 잔고와 외화 현금 요약 |
| 미국 현재가 | `/gbstock/quote/v1/current` | 미국 200, 티커 | 현재가와 시장 구분 |
| 미국 일봉 | `/gbstock/quote/v1/period` | 미국 200, 티커, 종료일 | 완료 정규장 OHLCV; 분할 조정 여부 미확정 |
| 미국 체결 | `/gbstock/inquiry/v1/unexecuted` | 연결 계좌, 주문일, 전체 체결 상태 | 실제 주문별 누적 체결; 정정·취소 연결은 검토 |

현재가는 0보다 큰 유한한 Decimal 값이어야 합니다. 앱은 가격, 수신 시각, 출처 `NH polling`을 함께 전달합니다. 수신 시각은 앱이 응답을 받은 시각이며 거래소의 정확한 개별 체결 시각은 아닙니다. 국내와 미국을 조회하며, 그 밖의 해외 시장은 사용자 입력으로 관리합니다. 폴링 방식이므로 WebSocket 체결 스트리밍과 다릅니다.

토큰은 서버가 알려준 만료시간과 24시간 중 짧은 기간을 적용하고 만료 직전에는 갱신합니다. HTTP 401일 때만 토큰을 한 번 강제 갱신합니다. HTTP 429는 기존 토큰을 유지하면서 최대 두 번 재시도하며, 각 대기는 최대 2초입니다. 그 뒤에도 실패하면 명시적인 오류를 표시합니다.

NH의 업무 응답 코드는 API에 따라 의미가 다를 수 있습니다. 모든 API에 하나의 성공 코드 목록을 적용하지 않고, 필요한 출력의 유효성과 오류 응답을 확인합니다. 비어 있는 체결 응답은 `조회내역이 없습니다`와 같은 명시적인 조회 없음 안내가 있을 때만 빈 결과로 인정합니다.

## 3. NH 체결 가져오기의 의미

한 번의 조회 기간은 양 끝 날짜를 포함하여 최대 367일입니다. 날짜별로 조회하고, 응답의 `cts`와 `cts_flag`를 다음 요청의 헤더로 전달합니다. 종료 표시가 없더라도 공식 SDK가 연속조회로 다루는 `00165`, `00218`과 연속조회 키가 있으면 다음 페이지를 받습니다. 키 누락, 반복되는 키, 불명확한 종료 상태, 페이지 상한 도달은 전체 가져오기 실패로 처리합니다.

가져오는 거래는 **일별 주문의 누적 체결 결과**입니다. 개별 체결을 원래 시각대로 재구성한 기록이 아닙니다.

| 원본 필드 | 처리 |
| --- | --- |
| `itg_orr_no` | 양의 정수 주문번호. 정렬용 `sequence`도 정수로 저장 |
| `iem_cd` | `KR:<코드>` 종목에 연결 |
| `sby_dit_cd_nm` | `매수`·`현금매수`는 `BUY`, `매도`·`현금매도`는 `SELL` |
| `tot_cns_qty` | 누적 체결 수량. 0이면 미체결 주문으로 건너뜀 |
| `cns_amt` | 값이 제공되면 체결금액을 수량으로 나눠 단가 계산 |
| `cns_avg_uit_pr` | 체결금액이 제공되지 않았을 때만 표시 평균단가로 사용 |
| `cfd_lon_cd` | 일반 현금 구분 `00`만 허용 |
| `org_itg_orr_no` | 0보다 크면 정정·취소 연결 관계를 안전하게 복원할 수 없어 가져오기 중단 |

금액을 수량으로 나눌 때 Decimal 유효숫자 50자리를 사용합니다. NH 화면의 표시 평균단가가 반올림되어 있을 수 있기 때문에 실제 체결금액을 우선합니다. 나눗셈이 유한 소수로 표현되지 않으면 아주 작은 반올림 차이가 생길 수 있으며 해당 행에 안내를 남깁니다. 제공된 금액이 0·음수·잘못된 수치이면 정상 체결로 받아들이지 않습니다.

같은 주문이 여러 페이지에 나타나면 누적 수량이 가장 큰 행을 사용합니다. 같은 누적 수량인데 단가가 다르거나, 같은 주문번호의 종목·매매 구분이 다르면 임의로 선택하지 않고 전체 가져오기를 중단합니다.

거래 식별자는 다음 구조입니다.

```text
nh:<계좌번호 SHA-256의 앞 24자리>:<YYYY-MM-DD>:<정수 주문번호>
```

실제 계좌번호는 거래 식별자나 내보내는 거래 행에 넣지 않습니다. 가져온 행의 `account_id`는 비워 두며, 앱의 가져오기 검토 화면에서 사용자가 선택한 로컬 계좌에 연결합니다. 반복 조회의 식별자는 유지됩니다. 앱에서 누적 주문 갱신을 선택하면 이미 가져온 주문의 증가한 수량을 검토하여 반영할 수 있습니다.

미국 체결은 `nh-us:<계좌 지문 24자리>:<NH 주문일자>:<주문번호>`를 사용합니다. 미국 200·현금 00만 지원하며, 취소·정정 연결 또는 다른 국가의 체결이 섞이면 해석을 중단합니다. NH 주문일자의 시간대가 확정되지 않아 원본 날짜를 유지합니다. 자동 실행의 체결 확인에서는 실제 주문 제출 시각과 상태 확인 시각을 별도 증거로 대조하므로, 미국 거래일과 다음 한국 날짜가 달라도 정확한 체결 시각을 만들어 내지 않습니다.

잔고는 기존 거래 위에 자동으로 더하지 않습니다. 거래 이력이 없는 종목만 현금 보유 확인 후 기초 보유 후보로 만들며, 과거 거래와의 중복을 차단합니다. 조회한 실제 계좌에 묶인 후보를 다른 저장 계좌로 바꾸면 저장을 거부합니다.

### 검토가 필요한 정보

- **수수료·세금:** 이 응답에서 확보하지 못하므로 둘 다 `0`으로 가져오고 경고를 표시합니다. 실제 거래명세서의 금액을 확인해 수정해야 손익에 반영됩니다.
- **체결 시각:** 조회 날짜를 저장하고 같은 날짜 안에서는 숫자 주문번호로 정렬합니다. 정확한 체결 시각이나 여러 주문의 교차 체결 순서를 보장하지 않습니다.
- **신용·대출·정정 주문:** 일반 현금 누적 체결로 안전하게 해석할 수 없는 주문이 섞이면 가져오기를 중단합니다.
- **장중 재조회:** 같은 주문의 누적 수량이 달라질 수 있습니다. 거래가 끝난 날짜를 조회하거나 누적 주문 갱신 결과를 검토하세요.

## 4. 키와 계좌 연결 정보의 로컬 보관

`SecretStore`는 Windows의 현재 사용자 DPAPI로 암호화한 바이너리 파일을 저장합니다. 컴퓨터 전체 공유 암호화 옵션을 사용하지 않으므로 다른 Windows 사용자에게 옮긴 파일은 그대로 사용할 수 없습니다. 데이터베이스·CSV·JSON의 거래 데이터와 별도로 보관하며, 내보내기나 GitHub 데이터 동기화에 비밀 파일을 포함하면 안 됩니다.

저장할 때 먼저 메모리에서 암호화하고, 암호문만 임시 파일에 쓴 뒤 원자적으로 교체합니다. 암호화 또는 파일 교체에 실패하면 이전 파일과 메모리 값을 유지합니다. 손상된 비밀 파일을 평문으로 해석하거나 평문 저장으로 전환하지 않습니다.

Windows 이외의 운영체제에서는 `supported=False`이며 **해당 실행 중의 메모리에만** 값을 보관합니다. 디렉터리나 비밀 파일을 만들지 않고, 새 실행으로 비밀 값을 넘기지 않습니다. 토큰 캐시에도 같은 규칙을 적용합니다.

## 5. 자동 수집 범위 밖의 자료

이 NH 어댑터는 배당 공시·예정일·실제 배당 입금을 자동 수집하지 않습니다. 앱에서 배당 참고 정보와 실제 계좌 입금은 별도 기록으로 관리해야 하며, 예정 배당을 수익으로 확정해서는 안 됩니다. CSV·엑셀·텍스트·OCR 가져오기 결과도 적용 전 검토 대상입니다.

## 6. 자동 실행 경계

조회용 `providers.py`와 실제 주문 경로 `nh_execution.py`를 분리했습니다. 미국 정수주 현금 지정가만 사용하며, 앱의 200티큐 자동 실행은 같은 거래일 정규장 종료 10분 뒤부터 NH 시간외 종료 전까지 진행합니다. 주문 전송은 한 번만 시도합니다. 응답을 모르면 UNKNOWN으로 보관하며, 주문번호 반환은 체결로 간주하지 않습니다. 매도대금은 실제 현금 증가 확인 뒤 재투자합니다. 지정가·수량·계좌·주문일자·전량 체결을 대조한 실제 NH 거래만 원장과 전략 단계에 연결합니다.

수수료·세금이 주문 상태에 제공되지 않으면 실행 경로는 0.5% 여유를 두되 비용을 확정하지 않습니다. 원장에는 확인 필요 표시를 남기고 다음 전략 단계는 실제 비용·남은 예산을 확인할 때까지 보류합니다. 주식 분할 조정이 미확정인 일봉도 해당 시계열 확인이 필요합니다. 실제 사용자 키를 이용한 API 검증은 수행하지 않았습니다.

거래 달력은 NYSE·Nasdaq의 2026~2028 예정 휴장·조기 종료를 사용합니다. 일정 밖의 연도는 추정하지 않고 중단합니다. 임시 휴장과 NH 시장 상태는 별도로 확인하며 달력만으로 주문을 허용하지 않습니다.
