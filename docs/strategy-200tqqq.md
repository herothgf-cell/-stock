# 200티큐 전략과 실행 계획

이 화면은 선택한 계좌의 실제 매매 원장과 TQQQ의 완료 정규장 종가로 **검토할 계획**을 계산한다. 전략 계산 자체는 증권사 주문을 호출하지 않으며, 계획을 만들었다고 매수·매도 내역이나 완료한 익절 단계가 생기지 않는다. 별도 자동 실행 계층도 이 계획과 실제 체결을 구분해야 한다.

## 적용한 원문

사용자가 제공한 아기티큐의 2026년 5월 7일 문서 「200티큐단은 실제로 언제 사고, 언제 팔고, 얼마나 익절하나」를 기준으로 구현했다. 공개 원문: <https://www.fmkorea.com/9797763685>. 아래 내용은 동작을 설명하는 요약이며, 제공 PDF와 전문은 공개 소스에 포함하지 않는다.

### 진입과 전량 정리

신호 종목은 **TQQQ**다. 정규장 종가가 자신의 200일선을 위로 돌파하면 첫날 매수용 현금의 1/3을 사용한다. 다음 거래일에도 종가가 선 위이면 남은 현금의 절반, 그 다음 거래일에도 선 위이면 남은 현금 전부를 사용한다. 분할 매수용 예산과 새로 들어온 돈을 혼합하지 않는다.

어느 날이든 종가가 선 아래이면 분할 매수가 진행 중이어도 TQQQ와 SPYM을 모두 정리하고 매도대금을 SGOV로 이동한다. 이 전략에 고점 대비 추가 손절이나 과열 이격도 규칙을 덧붙이지 않았다.

### 부분 익절

기준은 사용자의 **환차손을 포함한 계좌 TQQQ 수익률**이다. 종가의 USD 가격 변화만으로 이 수익률을 대체하지 않는다. 화면에서는 같은 미국 종가일에 해당하는 증권사의 TQQQ 수익률을 직접 입력한다.

| 사이클 내 처음 도달한 수익률 | 당시 남은 TQQQ에서 검토할 매도 비율 | 매도대금의 목적지 |
| --- | --- | --- |
| +10% | 10% | SPYM |
| +25% | 10% | SPYM |
| +50% | 10% | SPYM |
| +100%, +200%, +300% … | 각 50% | SPYM |

완료한 단계는 같은 사이클에서 다시 실행하지 않는다. SPYM에 옮긴 자금은 그 사이클의 TQQQ 추가 매수에 되돌리지 않는다. 전량 정리가 끝나면 다음 사이클은 새로운 상향 돌파에서 시작한다.

### 새 자금과 인출

TQQQ를 보유하고 종가가 200일선 위일 때 새 자금의 기본 방향은 SPYM 50%, SGOV 50%다. 선 아래에서는 SGOV가 목적지다. 원문은 매우 작은 금액에 대해 SPYM만 사용하는 선택도 설명한다. 인출 순서는 SGOV, SPYM, TQQQ다.

**현재 전략 화면의 현금 칸은 TQQQ 분할 매수에 남겨 둔 예산**이다. 계좌 전체 현금이나 별도 입금을 자동으로 뜻하지 않는다. 위 새 자금·인출 규칙은 화면에 안내하며, 금액을 정하지 않은 입출금을 추정하거나 주문으로 만들지 않는다.

## 사용 순서

1. 상단에서 계좌 하나를 선택한다. 다른 계좌의 보유량·원가·진행 단계를 합산하지 않는다.
2. `NH TQQQ 종가 조회`로 최근 260개 일봉을 받거나, UTF-8 CSV를 연다. CSV는 `date,close` 열과 `YYYY-MM-DD` 날짜를 사용한다. `날짜,종가`도 지원한다.
3. NH의 해당 일봉 응답에는 분할 보정 여부를 보장하는 필드가 없다. 보정 가격을 제공하는 원본과 비교하거나 기간 중 분할이 없었는지 검토한 뒤 `현재 가격 자료 확인`을 누른다. 이 버튼은 가격을 보정하는 기능이 아니다. 확인은 계좌별로 현재 전체 가격 자료의 해시에 연결되므로 종가 자료가 달라지면 다시 확인해야 한다.
4. 분할 매수용 USD 현금과 증권사가 허용하는 수량 단위를 입력한다. 기본 단위는 1주다. SGOV를 보유하고 있더라도 이 화면은 평가액을 가용 현금으로 간주하지 않는다. 매수 재원을 확보했다면 실제 사용 가능한 현금으로 입력한다.
5. 익절을 확인하려면 같은 종가일의 환차손 포함 수익률과 그 미국 날짜를 입력한다. 빈 수익률에서는 USD 수익률을 참고로 보여 주지만 익절 신호를 만들지 않는다.
6. 기존 TQQQ 보유분은 `기존 사이클 연결`에서 실제 시작일, 마지막 매수 신호일, 완료한 분할 매수 차수와 이미 실행한 익절 단계를 연결한다. 이 작업은 기초 잔고나 가상 매수를 만들지 않는다.

예시 CSV:

```csv
date,close
2026-10-23,100.1234
2026-10-26,110.00
```

위 두 행은 형식을 설명하는 합성 예시다. 실제 판단에는 **서로 다른 완료 정규장 종가 201개 이상**이 필요하다. 오늘과 전일의 200거래일 평균을 각각 계산하기 때문이다.

## 계획과 실제 체결 연결

`선택 계획 보관`은 현재 앱 실행 동안 계산 결과를 기억한다. 실제 증권사 체결을 매매 기록에 입력하거나 가져온 다음 `보관 계획 체결 연결`에서 해당 체결을 선택한다. 앱을 다시 시작할 때 보관 계획은 복원되지 않는다. 자동 실행 계층의 내구성 있는 주문 의도 저장은 이 수동 보관과 별개다.

체결 연결은 다음 조건을 검사한다.

- 계좌, 종목, 통화, 매수·매도 구분이 계획과 일치한다.
- 계획을 만든 시점에 이미 존재하던 체결이나 다른 계획에서 사용한 체결을 재사용하지 않는다.
- 신호일 이전 기록과 미래 기록을 거부한다. 시간대가 있는 체결은 신호일의 정규장 종료 전 기록도 거부한다. 날짜만 입력한 체결은 정확한 장 마감 후 시간을 사용자가 확인해야 한다.
- 분할 매수의 실제 수수료·세금 포함 비용은 해당 차수의 예산 이하여야 한다. 익절·전량 정리의 실제 수량은 선택한 계획과 같아야 한다.
- 여러 단계 시나리오를 실행했다면 낮은 단계의 실제 체결부터 연결한다. 같은 실제 체결을 여러 단계에 중복 연결할 수 없다.

확인된 익절 순매도대금은 `SPYM 대기금`으로 따로 남는다. SPYM을 일부만 매수했다면 사용하지 않은 대금이 다음 계획에 표시된다. TQQQ 분할 매수 예산으로 합산하지 않는다. 전량 정리는 TQQQ와 SPYM 실제 잔고가 0이고 계획한 매도 연결이 모두 완료되어야 사이클을 끝낸다.

단순히 모든 실제 보유분을 이미 정리한 상황이라면 `사이클 종료`로 마무리할 수 있다. TQQQ 또는 SPYM이 한 주라도 남아 있으면 종료하지 않는다. 실제 매매 원장과 기존 확인 기록은 유지한다.

## 원문에서 확정하지 않은 부분의 구현 선택

| 항목 | 현재 처리 |
| --- | --- |
| 200일선의 정확한 계산식 | 분할을 일관되게 보정한 **200거래일 단순이동평균**을 사용한다. 달력 200일이 아니다. |
| 종가와 평균이 정확히 같음 | 보유·보류. 그날은 매수나 매도 계획을 만들지 않는다. |
| 부분 매도 수량 | 지정한 수량 단위로 `ROUND_HALF_UP` 반올림하고 실제 보유량을 넘지 않게 한다. 기본은 정수 주식이다. |
| 매수 수량 | 종가로 계산한 예산 범위에서 수량 단위 아래로 내린다. 실제 주문 가격·수수료가 다르면 실행 전에 다시 계산해야 한다. |
| 소량 보유에서 0주로 반올림 | 강제로 1주 매도하지 않으며, 해당 익절 단계를 자동 완료하지 않는다. 수동 검토 대상으로 표시한다. |
| 하루에 여러 익절선을 넘음 | 낮은 단계부터 남은 수량에 순차 적용한 시나리오를 제시하고 수동 판단 대상으로 표시한다. 자동 주문 승인을 뜻하지 않는다. |
| 매수와 익절 조건이 같은 날 발생 | 처리 순서가 원문에 없으므로 수동 검토 대상으로 표시한다. |
| 예정된 다음 분할 매수일을 놓침 | 다음날 한꺼번에 따라 사지 않는다. 실제 이력을 검토하여 진행 단계를 다시 연결한다. |
| 원가 참고 계산 | 매매 원장의 수수료·세금을 포함한 남은 USD 원가를 수량으로 나눈다. 환율을 포함한 익절 수익률과는 별개의 참고값이다. |

정수 주식 예를 들면 100주에서 +10%의 10주, +25%의 9주, +50%의 8주를 팔면 73주가 남는다. 다음 +100% 단계에서 36.5주는 37주로 반올림되어 36주가 남는다. 수량 단위가 0.001주라면 그 단위로 반올림한다. 자동 주문 연동은 해당 증권사 API의 소수점 매매 지원 여부를 별도로 확인해야 한다.

## 가격의 시각·분할·최신성

미국 `America/New_York` 시간대와 NYSE가 공시한 **2026~2028년 휴장·조기폐장 일정**을 사용한다. 2026년 일정은 Nasdaq 달력과 교차 확인했다. 실제 정규장 종료 후 10분이 완료 기준이다. 통상 뉴욕 16:10, 조기 폐장일은 13:10이며 서머타임을 반영하므로 한국 시각을 05시로 고정하지 않는다. `tzdata`는 Windows에서도 시간대를 읽을 수 있도록 배포에 포함한다. 근거: [NYSE 시간·달력](https://www.nyse.com/trade/hours-calendars), [Nasdaq 거래 달력](https://www.nasdaqtrader.com/trader.aspx?id=Calendar).

최신 종가일은 그 시각에 이미 완료된 실제 거래소 세션과 일치해야 한다. 예를 들어 2026년 11월 27일 조기 폐장일 13:10 전에는 추수감사절 전날인 11월 25일을, 13:10 이후에는 11월 27일을 기대한다. 오래된 자료에 사용자가 확인 표시를 해도 최신성 차단을 해제하지 않는다. 검증 범위 밖의 연도는 달력 갱신 전까지 신호를 차단한다. 예고 없는 휴장이나 증권사별 운영 시간은 정적 달력으로 보장하지 않으므로 실행 전에 실제 증권사 상태를 확인해야 한다.

장중·미래 날짜, 중복 날짜, 주말 날짜, 7일을 넘는 데이터 공백은 신호를 차단한다. 큰 가격 단절은 분할·병합 또는 오류를 확인하도록 요구한다. **NH 가격의 분할 보정 확인은 새 가격 자료 해시마다 필요하므로, 현재 NH 응답만으로 모든 거래일을 무인 운용한다고 볼 수 없다.** 일관된 보정 출처의 도입 또는 매일 자료 검토가 필요하다.

저장한 증권사 수익률은 **계좌 + 미국 종가 날짜 + 해당 TQQQ 매매 기록의 해시**에 연결한다. 날짜나 TQQQ 기록이 바뀌면 그 수익률로 새 익절을 만들지 않는다. 같은 종가 자료와 원장 상태에서는 다시 계산해도 동일한 계획 ID가 생성되며, 계좌가 다르면 최초 진입 계획 ID도 다르다.

## 첨부 Toss 3.96과의 관계

사용자가 제공한 `toss-trader-release3.96`은 주문 전 의도 저장, 주문 단위 식별자, 실제 체결 대조, 단계별 재개, 불명확한 체결에서의 진행 중단 구조를 참고하는 자료다. 그 프로그램의 기본 투자 규칙은 제공 PDF와 동일하지 않다.

| 비교 항목 | 제공 PDF / 이 전략 | Toss 3.96 소스의 기본 동작 |
| --- | --- | --- |
| 진입 | 바로 3차 분할 | 대기 1일, 분할 기본값 1 |
| 추가 손절 | 별도 규칙 없음 | 사이클 고점 대비 25% 하락 시 50% 매도 |
| 과열 | 별도 규칙 없음 | 기본 200일선의 1.05배, 목적지·분할 진행 변경 |
| 낮은 익절선 | +10/+25/+50 각각 10% | 기본 +50에서 30% |
| 익절 대금 | 전액 SPYM | 원금 부분 SPYM, 수익 부분 SGOV |
| 여러 익절선 동시 통과 | 원문 미명시, 수동 시나리오 | 가장 높은 단계 하나를 선택하고 낮은 단계는 건너뜀 |
| 수량 | 원문 예시에 맞춘 반올림 | 정수 내림, 소수점 관리 종목 거부 |
| 수익률 | 환차손 포함 계좌 기준 | USD 종가 / 평균 매수가 |
| 새 자금 | 선 위 SPYM·SGOV 반반 | 보통 구간 주종목, 과열 구간 SPYM |

위의 차이를 숨기고 첨부 프로그램의 기본 설정을 그대로 가져오지 않는다. 전략 계산과 증권사 실행 구조를 분리해, 자동 실행이 필요할 때도 확정한 규칙과 저장한 주문 의도를 사용한다.

## 개발 인터페이스

`stockjournal.strategy.evaluate(state, account_id, history, *, cash_usd=None, quantity_step=None, broker_return_pct=None, now=None)`는 원장을 바꾸지 않고 `Decision`을 반환한다. 핵심 필드는 `account_id`, `as_of`, `history_hash`, `evaluated_at`, `blockers`, `manual_review`, `positions`, `actions`다. 각 `Action`은 안정적인 `id`, `kind`, `symbol`, `quantity`, `budget_usd`, `threshold_pct`, `entry_number`와 근거를 담는다. 종류는 `BUY_ENTRY`, `SELL_PROFIT`, `EXIT`, `BUY_SPYM`이다.

`confirm_action`은 실제 원장 거래 ID로만 완료를 확인하고 새 상태를 반환한다. `confirm_history`, `update_preferences`, `adopt_cycle`, `reset_cycle` 역시 원본 상태를 수정하지 않는다. 설정과 진행 단계는 계좌 레코드의 선택 필드 `strategy_200tqqq`에 보관해 기존 `schema_version=1`을 유지한다. 가격 캐시는 개별 PC에 있고, 계좌 설정은 개인 원장 동기화 대상이다. 공개 저장소에 실제 계좌 설정·가격 확인 기록·원장·인증값을 넣지 않는다.

`decision_to_dict`는 `Decision`을 일반 JSON 객체로 만들며 모든 금액·수량을 정확한 소수 문자열로 저장한다. `decision_from_dict`는 같은 필드를 `Decimal`과 `Action`으로 복원한다. 복원은 재조회·재계산을 하지 않으므로 저장한 계획의 의미가 바뀌지 않는다. 실행 계층은 원본 계좌, 사이클, 가격 해시, 계획 ID와 실제 체결 ID를 함께 보관하고 확인해야 한다.

NH가 제공한 업무일은 미국 시각보다 하루 앞선 한국 날짜일 수 있다. 자동 실행 연결은 검증한 주문 핸들의 제출 시각과 실제 전량 체결을 관찰한 시각을 `confirm_action(..., execution_evidence={trade_id: {submitted_at, observed_at}})`로 전달할 수 있다. 이때 신호 정규장 종료 ≤ 주문 제출 ≤ 체결 관찰 ≤ 현재 시각을 검증하고, 원본 NH 업무일이 제출 시각의 미국·한국 날짜 중 하나인지 확인한다. 원장의 NH 업무일은 그대로 보존하며 개별 체결 시각을 만들어 넣지 않는다. 이 근거가 없는 날짜만 있는 일반 기록에는 기존 보수적 날짜 검사를 유지한다.

`cash_usd`는 영구적인 투자 한도가 아니라 남은 분할 매수 재원이다. 자동 실행 계층은 전량 정리 후 실제 순매도대금과 미사용 재원으로 다음 사이클 재원을 갱신할 수 있다. 수수료·세금이 응답에 명시되지 않았다면 임의의 0원을 순매도대금의 증거로 쓰지 않는다. 이때 `reserve_review_required`와 사유를 남겨 다음 진입을 차단한다. SGOV에 들어 있는 재원을 주문 가능한 현금처럼 사용하지 않으며 실제 매도와 가용 현금 확인이 선행되어야 한다.

실제 매도 비용이 확인되지 않은 실행은 `costs_review_required`도 남긴다. 이 표시가 있으면 추가 TQQQ 매수·부분 익절·SPYM 재투자를 보류하되, 선 아래에서의 전량 정리는 허용한다. 사용자는 증권사의 확정 수수료·세금을 원장에 반영하고, 분할 매수용 재원과 `확인한 SPYM 대기금 USD`를 실제 금액으로 수정한 다음 **`실제 체결 비용·남은 예산을 확인했습니다`**를 선택해 저장한다. 체크하지 않은 일반 저장은 비용 불확실성을 해제하지 않는다. 개발 API는 `update_preferences(..., pending_spym_usd=..., costs_reviewed=True)`이며 진행 중인 사이클의 비용을 해제하려면 SPYM 대기금을 명시해야 한다. 미확정 비용 때문에 생기는 수동 확인도 완전 무인 운용의 제약이다.
